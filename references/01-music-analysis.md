# 01 — 音乐与源素材分析

## 目标

先确认“这首歌实际是什么、唱了什么、声音如何组织”，再开始视觉创作。

## 1. 素材盘点

列出实际发现的文件及其类型：
- 源视频；
- 音频文件；
- 专辑封面或宣传图；
- 歌词/字幕文件；
- 参考视频或图片；
- 已有工程文件；
- 可复用模型和脚本。

保留原始路径。不要根据文件名推断内容。

## 2. 歌曲资料

核对歌名、歌手、专辑、发行年份、版本类型（录音室 / LIVE / remix / acoustic 等）。

报告中区分：
- `源文件可确认`
- `外部来源确认`
- `推测 / 待确认`

封面分析记录构图、人物位置、服装、发型、主要形状、色彩、材质和标志性细节。封面没有明确显示的信息不得推断为事实。

## 3. 完整音频检查

从头听到尾，检查：
- 倒放、反向混响、磁带倒转；
- 电话音、收音机、窄带滤波；
- 口白、讲话、耳语、呼吸、叹息、笑声；
- 合唱、和声、重复口号、数数、count-in；
- 现场欢呼、掌声、观众合唱、舞台噪声；
- 特殊瞬态、静音、突然切断、隐藏音效。

可用波形、频谱、声道差异、人声能量辅助定位。算法结果只能作为线索，听感核验优先。

若发现特殊声音，记录时间码、证据、置信度和剧情潜力。没有发现就明确写“未发现明显特殊声音”，不要人为补造。

## 4. 歌词与字幕

优先检查源视频是否有烧录字幕。可用现有工具执行字幕框定位、提取和位图化；脚本名称以仓库实际文件为准。

若源字幕不可读：
1. 查找用户提供或合法可用的歌词文本；
2. 将文本与实际人声逐句核对；
3. 逐句记录起止时间；
4. 无法确认的字词标记为 `[听辨不清]`；
5. 不根据记忆补齐歌词。

歌词用于项目字幕时，以用户提供/授权的素材和项目内实际核对结果为准。普通报告只引用必要短句，不粘贴整首歌词。

## 5. BPM、节拍与段落

先判断速度是否恒定：
- 恒定：拟合固定节拍网格；
- 不恒定：建立逐拍 beat map；
- 半拍 / 双倍 BPM 误判：用低音、和弦变化、旋律重音交叉检查。

小节第一拍优先参考低音和和弦换位，不单纯选择最响的底鼓。

如项目中存在 `beats.py`、`grid.py`、`beatmap.py`、`kicks.json`，先检查用法和版本，再运行。不得假设这些文件必然存在。

记录：
- BPM 或变化范围；
- 拍号；
- 网格置信度；
- 小节编号规则；
- 前奏、主歌、副歌、间奏、桥段、尾奏起止时间；
- 各段起止小节；
- 需要人工复核的切点。

统一格式：`B(bar, beat)`。同时保留实际时间码，避免只靠小节编号剪辑。

## 6. LIVE 特殊规则

如果确认是 LIVE / 演唱会版本：
- 保留现场声场、观众反应和演出空间；
- 核实演唱会名称、场地和年份；未核实则标注未知；
- 视觉可设计舞台、观众席、安可、后台或 STAFF ROLL，但必须符合素材与创意；
- 不得将棚录版本伪装成 LIVE。

## 7. 阶段一报告格式

使用 `templates/analysis-report.md`。至少包含：
- 文件清单；
- 歌曲资料及证据来源；
- 特殊音频发现；
- 歌词段落及时间码；
- BPM / 节拍 / 小节规则；
- 音乐段落表；
- 封面视觉母题；
- 未知项与待确认项；
- 建议进入创意阶段的线索。
